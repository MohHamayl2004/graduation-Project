# Codex + Gemini delegation

Run `python scripts/delegate_gemini.py .agents/tasks/gemini-smoke.json` (Windows: `py -3` also works). The runner finds agy on PATH or at `%LOCALAPPDATA%\agy\bin\agy.exe`. It requires Python 3.10+, Git, and an authenticated Antigravity CLI. No new Python dependencies.

For development, write an ignored task JSON under `.agents/runs/` with `id`, `task`, exact writable `files`, exact `contextFiles`, `acceptance`, `apiContract`, `readOnly`, and `checks` as argument arrays. Example build check: `["npm.cmd", "run", "build", "--", "--outDir", ".agents/check-output/build"]`. Default model is `gemini-4-argon-medium`; high requires `model: gemini-4-argon-high` and a meaningful `complexityReason`. Include dependency manifests and API contracts as context when relevant. Never include credentials, environment files, or private documents.

Check commands may write disposable generated output only under `.agents/check-output/`; it is retained in the worktree but excluded from the final code patch. Gemini-created files in that same location are still rejected before checks. Other changes made by checks are captured and block acceptance, including an ordinary Vite build that overwrites tracked dist files. Configure test caches, coverage and build destinations accordingly. Codex installs necessary dependencies in the isolated worktree before checks; the runner does not automatically install packages or copy node_modules.

Each run creates a detached `.worktrees/gemini-<id>` at HEAD and overlays listed current files, including untracked task files and current deletions, plus the current AGENTS.md and .gitignore. Other uncommitted changes are absent: Codex must name all relevant context, or keep that task local. No node_modules, secrets, or personal CLI settings are copied into the worktree overlay. A worktree isolates files, not the entire machine; agy's sandbox and normal permission policy also remain enabled. File scope is checked after execution; it is not an OS security boundary.

The runner serializes Gemini tasks with an exclusive lock. Codex reserves writable files until Gemini returns. Artifacts under `.agents/runs/<id>/` include the prompt, raw stdout/stderr, measured usage, checks, actual changed-file list, a binary-capable patch, and `result.json`. They are ignored and may contain source; do not publish them. Worktrees are retained for review, not applied automatically. Never copy runtime records into shared project context.

`needs_review` means only that CLI status, scope, source fingerprints, and specified checks passed. `accepted` remains false. Codex must inspect the actual patch, compare acceptance criteria and real API contracts, inspect imports/dependencies/security, and run appropriate build/tests and useful browser checks. CLI success is not implementation success. Check stderr: headless permission denials can accompany exit zero ([Google's headless documentation](https://antigravity.google/docs/cli/headless/)).

After review, Codex may run `git apply --check <run>/changes.patch`, apply the patch to the current development branch, and verify the integrated result. If the original context changed, rebase the task context first; never force a stale patch. Record Codex's review decision, check evidence, quality/reliability and measured time/tokens in the ignored run directory. Nothing automatically merges, pushes or deploys. Major visual changes require the user's design approval.

One correction cycle maximum: issue a new narrowly scoped task with the defect list and the first worktree as `--repo`, with its affected files as the current context; inspect both patches relative to the original baseline before applying. This does not automatically resume Gemini's previous conversation. Do not retry authentication, permissions, missing models or timeouts repeatedly. Report the exact blocker and keep artifacts. Never use the permission-bypass flag or substitute a model. A stale lock is removed only after verifying its recorded process is no longer running. Clean reviewed worktrees with `git worktree remove <exact-path>`; preserve unreviewed patches.

The initial smoke test is read-only. Offline tests use disposable repositories and a deterministic CLI double; they exercise patch generation, scope failures, timeouts, zero-exit errors, authentication/permission failures, and failed automated checks without changing production features or spending model tokens.
